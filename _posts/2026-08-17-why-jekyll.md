description: "Why this site moved from a plain static build to Jekyll."
tags:
  - "website"

---

Jekyll is a good fit for this project because the site is mostly static content but needs a lot of repeated structure.

Instead of copying the same header, footer, project card, and metadata blocks into every file, Jekyll can generate them from layouts and includes.

Collections also make project records much easier to manage. A project can live in its own Markdown file and automatically appear in the project archive.
